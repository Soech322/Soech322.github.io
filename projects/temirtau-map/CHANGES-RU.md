## Обязательное применение защиты в Firebase

Одного обновления интерфейса недостаточно: существующие download-token ссылки обходят Firebase Storage Rules. В коде новых загрузок такие ссылки больше не публикуются. Для старых файлов нужно отозвать токены. Без этих действий старые ссылки продолжают работать.

1. Разместить обновлённые файлы сайта на текущем хостинге, включая `js/photos.js` и `sw.js`.
2. Из папки проекта опубликовать правила с правами владельца проекта:

```powershell
firebase deploy --project mapb-a3590 --only firestore:rules,storage
```

3. Установить операторскую зависимость. Настроить Application Default Credentials учётной записи с доступом к Firestore и метаданным Storage, например через `gcloud auth application-default login`. Не помещать ключи или credentials в файлы сайта.

```powershell
Set-Location tools
npm install
node privatize-photos.cjs --project mapb-a3590 --bucket mapb-a3590.firebasestorage.app
```

Последняя команда выполняет только dry-run и выводит число файлов/документов. Проверив проект и bucket, применить:

```powershell
node privatize-photos.cjs --project mapb-a3590 --bucket mapb-a3590.firebasestorage.app --apply
```

Скрипт отзывает download-токены всех объектов в `registry-photos/` и `card-photos/`, включая файлы без текущей ссылки в карточках. Сами изображения и геоданные не удаляются. После каждого обновления метаданных проверяется отсутствие токена. Миграцию можно повторять. При частичном сбое повторный запуск завершает оставшуюся работу. Не запускайте её параллельно со старыми клиентами, загружающими фото; после публикации обновите открытые вкладки администраторов.

`tools/`, `tests/`, `node_modules/`, credentials и этот документ не требуется размещать на публичном хостинге. Конфигурация `firebase.json` сохранена: Hosting в исходном проекте не был настроен, поэтому способ публикации статических файлов не менялся.

## Проверка после публикации

- В приватном окне без входа открыть карточку: раздела фото и счётчика фото нет; запрос изображения к Storage без авторизации отклонён. Повторить с вошедшим пользователем без документа admins/{uid}.
- Проверить ранее скопированный публичный URL: после миграции он больше не возвращает файл.
- Войти администратором. В Network при открытии карточки и разворачивании «Фотографии» запросов изображений нет. Нажать «Показать фото»: появляется один авторизованный запрос; повторный просмотр использует память. Выйти: раздел скрывается, blob URL отзываются.
- Отключить сеть и нажать ещё не загруженное фото: увидеть ошибку; восстановить сеть и повторить. Для уже загруженного фото допускается просмотр из памяти в текущей сессии.
- На компьютере и телефоне выбрать территорию, повернуть карту на 45/135/270 градусов, изменить масштаб и переместить её. Граница следует географическим координатам, остаётся кликабельной. Отдельно проверить редактирование вершин и отмену.
- Перед построением маршрута запомнить центр, zoom, bearing и масштаб страницы; построить маршрут дважды, включая запасной сервис. Камера и страница не меняются. Проверить ввод адресов на iOS: фокус поля не увеличивает страницу.

Уже скачанные ранее копии фотографий невозможно удалить с чужих устройств; миграция закрывает последующие серверные загрузки по старым ссылкам.

## Основание исправления географических слоёв и авторизации

В исходном коде leaflet-rotate v0.2.8 `tilePane` и `overlayPane` помещаются в `rotatePane`, а обычный `createPane` не переопределён. Поэтому исправление использует `createPane(name, map.getPane('overlayPane'))`, сохраняя L.polygon и исходную геометрию: https://github.com/Raruto/leaflet-rotate/blob/v0.2.8/src/map/Map.js

Заголовок запросов с Firebase ID token соответствует реализации Firebase Storage SDK (`Authorization: Firebase <token>`): https://github.com/firebase/firebase-js-sdk/blob/main/packages/storage/src/implementation/request.ts
