# Как открыть исправленную версию

Откройте **index.html**. В нём уже встроены стили, иконки, данные и библиотеки карты/Firebase. Для интерфейса не нужны соседние папки, сервер или CDN. Для спутниковой подложки, маршрутов, синхронизации и Firebase требуется интернет.

Файл **index.template.html** предназначен для разработки. После изменения CSS/JS или данных выполните `node build.cjs`: он пересоберёт index.html и отдельный КАРТА-ОТКРЫТЬ.html рядом с папкой проекта.

Для установки PWA используйте HTTP(S) и полную папку проекта. Публикация правил Firebase и миграция старых фотографий описаны в CHANGES-RU.md.

# Темиртау — рабочие карты

Веб-ГИС для контроля детских площадок, кадастровых зон и ремонтно-восстановительных работ (РВР) в Темиртау. Статический сайт без сборки: HTML + CSS + JavaScript, карта на Leaflet, данные и правки — в Firebase.

## Возможности

- **Два раздела:** «ГИС-контроль» и «Ремонтные работы».
- **Площадка и её кадастровая зона — один объект.** Иконка внутри полигона (или с тем же кадастровым номером) связывается с зоной: общая карточка, общий цвет и общий ответственный.
- **Ответственные.** У человека есть имя, телефон и цвет (свободный цвет подбирается автоматически). Включите фильтр «Показать назначенные площадки»: свободные объекты серые, закреплённые окрашены в цвет человека, над иконкой видны имя и телефон.
  - «Назначить на карте» — нажимайте на площадки подряд, и они закрепляются за выбранным человеком.
  - «Снимок» — PNG-лист со всеми территориями человека: карта, пронумерованные метки и список адресов.
- **Фильтр РВР** по видам работ (покраска, завоз песка, круглая карусель) и статусу: «Не выполнено» (по умолчанию), «Выполнено», «Все». В панели фильтров видна статистика выполнения.
- **Синхронизация с Google-таблицей выполненных работ** (`js/sheet-sync.js`). Таблица — список адресов, где работа уже сделана. Сайт читает её при открытии и раз в 5 минут:
  - адрес есть в таблице — работа «Выполнено», а карусель «Установлена»;
  - адреса нет — «Не выполнено» (карусель — «Не установлена»).

  Адреса сопоставляются с площадками по улице и номеру дома с учётом опечаток. **Меню → Сверка с таблицей** показывает ненайденные строки: их можно привязать к площадке вручную (привязки хранятся в `sheet_links`) или пропустить. Таблица должна быть открыта «для всех, у кого есть ссылка».
- **Реестр 133 детских площадок** (`playground-registry-data.js`, собран из «133 Детские площадки.xlsx», Лист2). «Проверка данных» сверяет его с картой по кадастровым номерам и показывает площадки, которых нет на карте, с кнопкой «Добавить на карту». После обновления xlsx файл данных нужно пересобрать.
- **ГИС: типы объектов.** Детские площадки, скверы и парки (зелёные) и прочие зоны — у каждого типа свой цвет, их можно скрывать. Счётчик показывает именно детские площадки.
- **Цвет объекта** админ может поменять вручную (карточка → «Цвет» или редактор).
- **Подложки:** спутник, тёмная, светлая (Esri, без ключа).
- **Языки:** русский, казахский, английский. Типовые термины в описаниях KML тоже переводятся.
- **Администрирование** (после входа): правка названий и описаний, перемещение точки, правка границ зоны, рисование новых зон, фото только для администраторов, по нажатию (до 2 на объект), журнал изменений с откатом, «Проверка данных».
- **Удобство:** поиск по объектам, домам и ТЦ; маршруты; геолокация с компасом; ссылка на объект (`#gis/gis-0001`); выгрузка в Excel (CSV); работа без интернета (PWA).

## Структура

```text
index.html             разметка
css/app.css            стили (тёмная тема, мобильная шторка)
js/icons.js            SVG-иконки
js/i18n.js             тексты RU / KK / EN и перевод терминов из KML
js/core.js             Firebase, вход, карта, подложки, поиск, маршрут, геолокация, диалоги
js/registry.js         объекты: объединение точка+зона, ответственные, фильтры, карточки, правка, журнал
js/snapshot.js         PNG-снимок территорий человека
sw.js, manifest.webmanifest, icon.svg   PWA
gis-control-data.js, repair-works-data.js, house-numbers-data.js, landmarks-data.js   исходные данные
firestore.rules, storage.rules, firebase.json   правила безопасности
rvr-import-tool.html   служебный импорт описаний/точек РВР
```

Порядок подключения скриптов задан в конце `index.html`: сначала библиотеки, затем данные, затем `js/*`.

## Настройка Firebase (обязательно, один раз)

Раньше пароль администратора лежал в коде страницы, а база принимала запись от кого угодно. Теперь права проверяет сам Firebase.

1. **Authentication → Sign-in method** → включить **Email/Password**.
2. **Authentication → Users → Add user**: создать аккаунты администраторов и скопировать их **User UID**.
3. **Firestore Database → Data**: создать коллекцию `admins`, а в ней документ с ID, равным UID пользователя. Поля можно не заполнять или добавить, например, `name`. Повторить для каждого администратора.
4. **Firestore Database → Rules**: вставить содержимое `firestore.rules` и нажать «Опубликовать».
5. **Storage → Rules**: вставить содержимое `storage.rules` и нажать «Опубликовать».

Правила можно опубликовать и через CLI: `firebase deploy --only firestore:rules,storage`.

Коллекции Firestore:

| Коллекция | Что хранит | Чтение | Запись |
|---|---|---|---|
| `gis_control_overrides`, `repair_works_overrides` | правки объектов поверх KML | все | админы |
| `assignees` | ответственные: имя, телефон, цвет | все | админы |
| `sheet_links` | ручные привязки строк Google-таблицы к площадкам | все | админы |
| `audit_log` | журнал изменений (до/после) | админы | админы, только добавление |
| `admins` | список администраторов | сам пользователь | только консоль |

> Имена и телефоны ответственных видны всем посетителям карты, потому что они подписываются над иконками. Если сайт публичный, учитывайте это.

## Защита описаний

История: шаг 4 импорт-тула сопоставлял строки таблицы по `name.includes(адрес)`. Пустая строка совпадала со всеми объектами, и 157 описаний (в том числе у скверов) были заменены шаблоном `Кадастровый номер:  Площадь:  кв.м Категория: `.

Что сделано, чтобы это не повторилось:

- Сайт игнорирует пустые или шаблонные описания и показывает исходное описание из KML.
- **Меню → Проверка данных** одной кнопкой удаляет испорченные описания из базы. Каждое действие записывается в журнал.
- Каждое изменение пишется в `audit_log`. В карточке объекта есть «История изменений» с кнопкой «Вернуть это описание».
- `firestore.rules` не даёт записать такой шаблон.
- Импорт-тул пропускает пустые строки, сравнивает адрес целиком, **дополняет** описание вместо замены и требует входа администратора.

## Локальный запуск

```bash
python -m http.server 8000
# открыть http://localhost:8000
```

Service worker работает только через http(s). Если после обновления сайта видна старая версия, увеличьте `VERSION` в `sw.js`.
